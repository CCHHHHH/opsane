# Shell Agent 聊天历史分批展开设计

## 背景

聊天会话恢复时，前端固定请求最近 140 条消息。后端会同时返回被省略的消息数量，但前端目前只显示“已折叠较早的 N 条历史消息”文本，没有提供展开按钮或继续加载逻辑。因此历史数据仍保存在 SQLite 中，用户却无法从页面查看。

## 目标

- 首次进入长会话时仍只加载最近 140 条，保持页面打开速度。
- 在消息列表顶部显示可操作的“加载更早消息”控件。
- 每次加载最多 140 条更早消息，直到完整历史全部可见。
- 加载完成后保持用户当前阅读位置，不跳回列表底部。
- 会话切换、自动刷新和待确认任务恢复不能把已展开的历史重新折叠。

## 非目标

- 不修改发送给大模型的上下文压缩策略。
- 不改变历史消息的存储格式和保留周期。
- 不增加独立的历史查看弹窗或新页面。

## 交互设计

当后端返回 `messages_truncated > 0` 时，在当前最早一条可见消息之前显示历史加载条：

```text
还有 214 条更早消息                         [加载更早 140 条]
```

点击后按钮进入禁用的“加载中”状态。加载成功时增加当前会话的消息窗口并重新渲染：

- 仍有历史时，更新剩余数量和下一批可加载数量。
- 历史已全部加载时，移除历史加载条。
- 用户视口保持在点击前正在阅读的内容附近。
- 加载失败时保留原消息列表，并通过现有 Toast 显示错误。

## 前端设计

1. 为每个聊天会话维护当前历史加载上限，默认值为 `140`。
2. `selectSession` 和 `refreshActiveSession` 使用该会话当前的加载上限，避免刷新后重新折叠。
3. `restoreChatSession` 不再把折叠状态渲染成普通系统消息，而是创建独立的历史加载控件。
4. 点击控件后，将请求上限增加 `min(140, messages_truncated)`，重新请求会话数据。
5. 重新渲染前记录消息容器的 `scrollHeight` 和 `scrollTop`；渲染后按新增高度补偿 `scrollTop`，保持阅读锚点。
6. 同一会话只允许一个历史加载请求，防止重复点击产生乱序响应。

## 后端设计

沿用现有 `GET /api/sessions/{session_id}?message_limit=N` 接口和尾部消息查询，不新增存储结构。

当前接口将正数 `message_limit` 截断到 500，这会导致超过 500 条的会话仍无法完整展开。该限制需要调整为允许前端按实际剩余数量逐批扩大窗口。`message_limit=0` 继续保留“返回全部消息”的现有语义，以兼容已有调用。

后端继续返回：

- `messages`: 当前窗口内按时间正序排列的消息。
- `messages_truncated`: 当前窗口之前仍被省略的消息数。

## 数据流

1. 进入会话，请求最近 140 条消息。
2. 后端返回 140 条消息及 `messages_truncated=214`。
3. 前端显示 140 条消息和“加载更早 140 条”控件。
4. 用户点击后，请求最近 280 条消息。
5. 前端重新渲染并补偿滚动位置，此时显示“还有 74 条更早消息”。
6. 再次点击后请求最近 354 条，`messages_truncated=0`，历史加载控件消失。

## 异常与并发处理

- 网络或接口错误：恢复按钮可点击状态，不改变现有消息。
- 会话已删除：使用现有“会话不存在”错误提示。
- 加载期间切换会话：响应返回后仅更新响应所属会话；不得覆盖当前活动会话。
- WebSocket 自动刷新：继续使用该会话已扩大的消息上限。
- 待确认命令或运行中任务：仍由现有恢复逻辑渲染，历史加载不得改变其状态和操作按钮。

## 验收标准

- 消息数不超过 140 的会话不显示历史加载控件。
- 消息数超过 140 的会话首次只显示最近 140 条和正确的剩余数量。
- 每次点击最多增加 140 条，并最终可以查看数据库中的全部历史。
- 加载更早消息后，用户当前阅读位置没有明显跳动。
- 页面刷新或会话自动刷新后，当前页面生命周期内已展开的消息数量不回退。
- 连续快速点击只发出一个有效加载请求。
- 历史加载失败不会清空聊天内容。
- 待确认命令、任务状态和执行结果不重复、不消失。

## 测试方案

- 后端测试：验证大于 500 的 `message_limit` 不再被静默截断，并正确返回 `messages_truncated`。
- 前端验证：使用超过 300 条消息的会话检查两次分批加载、剩余数量和控件消失。
- 滚动验证：在顶部加载前记录视口内容，加载后确认仍停留在相同消息附近。
- 回归验证：运行完整测试集，并检查短会话、待确认命令和会话切换流程。
